## Core loop
- Idle game built on ordinal numbers from set theory: start with a button that adds one. [S]
- Then autoclickers, factors, and factor shifts. [S]
- Goal is to climb a hierarchy of ever larger ordinals; the title of the Metafilter thread shows the display format "Next Ordinal Level is at psi(Omega^(Omega^2+omega))". [S]
- Numbers are displayed as ordinals (omega, epsilon_0, ... via collapsing functions) rather than decimals. [S]/[M]

## Resource types
- Ordinal value (main), charge/click value, autoclicker count. [M]
- Factor count and base: a factor shift lowers the base so the number goes straight from, e.g., 44 to 100 with base 5. [S]
- Later: Factor Boosts, Aleph Power and Singularities. [S]

## Lessons for my game (Kamen Rider Decade idle, sequential Rider worlds, upgrade-focused, no fighting)
1. Show the next gate as a named value ("Next level is at ...") instead of a bar; players plan around names. [S]
2. A reset that rewrites the rules (base change) is stronger than a plain multiplier; a Decade "world change" could rewrite one rule (cost base) instead of adding a number. [S]
3. Carry-over: players complained about the full wipe, so keep at least one item per reset. [S]
4. Progression by notation level suggests eras: each Heisei Rider is a "notation level" and numbers need not be large. [E]
5. Theming a number system (ordinals) gives zone-like progression with no combat; use named tiers in place of zones. [E]
6. Keep notation readable: show a plain-language description beside the formal one. [E]
